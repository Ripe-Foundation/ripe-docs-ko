# RIPE 보상: 프로토콜을 사용하고 보상받기

모든 블록. 모든 포지션. 대출하거나 스테이킹한 모든 달러.

Ripe Protocol이 확인하고 보상합니다.

전체 공급량의 4분의 1인 2억 5천만 RIPE가 블록 보상과 본드를 통해 프로토콜을 실제로 사용하는 사람에게 배정됩니다. VC도 내부자도 아닌 사용자입니다. GREEN을 대출받나요? 보상받습니다. 스테이킹하나요? 더 받습니다. 보상을 잠그나요? 더 많이 받습니다.

> **실시간 조건은 온체인에 있습니다.** 발행 속도, 카테고리 배분, 자산 가중치, 자동 스테이킹 비율, 잠금 조건은 배포 네트워크마다 다르고 시간에 따라 바뀝니다. 이 페이지의 모든 수치는 예시입니다. [Params](https://params.ripe.finance)가 최종 기준입니다.

## 빠른 시작: 보상 이해하기

**🎯 1분 요약:**

```
사용자 활동                 → 카테고리(배분 예시) → 사용자 몫
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
RIPE / RIPE LP 스테이킹     → 스테이커       90% → 풀의 몫 × 사용자 포인트 지분
sGREEN / GREEN LP 예치      → 스테이커       90% → 풀의 몫 × 사용자 포인트 지분
GREEN 대출                  → 차용자         10% → 사용자 대출 포인트 ÷ 전체 대출 포인트
기타 볼트 자산 예치         → 예치자          0% → 달러 가치 × 시간(활성화 전까지 꺼짐)
투표로 선정된 자산          → 투표자          0% → 커뮤니티가 결정(활성화 전까지 꺼짐)

포인트 = 잔액 × 블록. 풀에서 사용자 지분 = 사용자 포인트 ÷ 풀 전체 포인트.
```

**💡 핵심:** 모든 사용자와 경쟁하는 것이 아니라 같은 풀의 사용자와만 경쟁합니다. 차용자는 스테이커의 몫을 희석하지 않습니다. sGREEN 예치자도 RIPE LP 스테이커의 몫을 희석하지 않습니다.

## 보상 엔진

### 모든 블록이 중요합니다

보상은 주간 에폭으로 지급되지 않습니다. 블록마다 보상 배정 한도에서 고정된 RIPE 수량이 보상 풀에 더해지고, 네 가지 카테고리의 가중치에 따라 나뉩니다. 가중치는 정규화됩니다. 90/10/0/0이면 매 블록 발행량의 90%를 스테이커가, 10%를 차용자가 받습니다.

청구하기 전에는 아무것도 발행되지 않습니다. 받을 권리만 배정 한도에서 누적되고, 실제 수령하는 순간 토큰이 만들어집니다.

같은 배정 한도를 사용하는 항목이 두 가지 더 있습니다. 아래에서 설명하는 [안정화 풀 청구](02-stability-pools.md) 시 지급되는 RIPE, 그리고 거버넌스가 활성화한 경우 Underscore 지갑 사용자에게 정기적으로 지급되는 RIPE입니다.

### 포인트 시스템

```
포인트 = 잔액 × 보유 블록
```

공식은 이것이 전부입니다. 오래 유지한 작은 포지션이 잠깐 머문 고래보다 더 많이 받을 수 있습니다. 수학을 통한 공정한 배분입니다.

볼트와 자산의 각 조합은 자체 전체 포인트를 가진 별도 풀입니다. 같은 토큰을 서로 다른 두 볼트에 보유하면 두 개의 풀에서 따로 보상받습니다.

## 보상 카테고리

### 1. 스테이커(예시에서 90%) 💎

[**거버넌스 볼트**](../governance-and-economics/02-governance.md) **(RIPE 및 RIPE LP)**

* **잠금 배수**: 더 오래 잠글수록 포인트가 늘어납니다. 최대 기간 잠금에는 최대 3배가 적용됩니다. 배수는 이미 사용자의 포인트 지분에 반영됩니다.
* **LP 이점**: RIPE LP에는 자체 자산 가중치가 있으며 예시에서는 가장 큽니다.
* **복리**: 청구한 보상이 볼트에 다시 스테이킹되므로 보상이 다시 보상을 얻습니다.

[**안정화 풀**](02-stability-pools.md) **(**[**sGREEN**](01-sgreen.md) **및 GREEN LP)**

* **세 가지 수익**: sGREEN 수익, 청산 수익, 추가 RIPE입니다.
* **잠금 불필요**: 풀이 허용하는 동안 언제든 출금할 수 있습니다.
* **청구 보상**: 풀에서 청산 담보를 청구하면 청구한 달러당 추가 RIPE를 받습니다. 이 RIPE는 유동 수령분 없이 보상 잠금이 적용된 거버넌스 볼트로 100% 들어갑니다.

### 2. 차용자(예시에서 10%) 💰

GREEN을 대출받으면 원금이 블록마다 포인트를 얻습니다.

* **포인트**: 미상환 원금 × 대출 유지 블록
* **사용자 몫**: 사용자 대출 포인트 ÷ 전체 대출 포인트
* **실질 혜택**: RIPE 수익이 이자 비용을 상쇄합니다.

### 3. 일반 예치자(예시에서 0%)

거버넌스는 스테이커로 이미 보상받지 않는 기타 모든 볼트 예치 자산에 달러 가치 × 블록으로 가중한 보상을 활성화할 수 있습니다.

### 4. 투표자(예시에서 0%)

거버넌스는 투표를 통해 특정 자산에 보상을 배정하여 프로토콜에 필요한 곳으로 유동성을 유도할 수 있습니다.

## 사용자 몫 이해하기

### 자산 가중치

스테이커 카테고리 안에서 각 자산에는 가중치가 있습니다. 예시:

* RIPE LP: 45
* GREEN LP: 25
* sGREEN: 15
* RIPE: 15

고정 비율이 아니라 가중치입니다. 각 풀은 블록마다 자산 가중치만큼 카테고리 포인트를 쌓고, 해당 카테고리에서 풀의 몫은 풀 포인트 ÷ 카테고리 전체 포인트입니다. 이 네 개의 풀만 있고 가중치가 유지된다면 각각 45% / 25% / 15% / 15%가 됩니다.

### 보상이 실제로 흐르는 방식

```
전체 RIPE 발행량(예시: 하루 500 RIPE)
            ↓
    ┌───────┴───────┐
    │ 1차 배분      │ (카테고리 가중치 기준)
    └───────┬───────┘
            ↓
    90% → 스테이커
    10% → 차용자
     0% → 예치자, 투표자
            ↓
    ┌───────┴───────┐
    │ 2차 배분      │ (카테고리 안의 풀 기준)
    └───────┬───────┘
            ↓
    풀의 몫 = 풀 포인트 ÷ 카테고리 포인트
            ↓
    사용자 몫 = 사용자 포인트 ÷ 풀 포인트
```

차용자는 2차 배분을 건너뜁니다. 사용자 대출 포인트 ÷ 전체 대출 포인트로 끝입니다.

### 단계별 계산 가이드

**🎯 1단계: 어떤 카테고리인가요?**

```
RIPE, RIPE LP, sGREEN, GREEN LP 스테이킹 → 스테이커(90%)
GREEN 대출                                → 차용자(10%)
```

**🎯 2단계: 사용자 풀이 차지하는 몫은 얼마인가요?**

```
하루 500 RIPE × RIPE당 $10 = 하루 $5,000
스테이커: 하루 450 RIPE    차용자: 하루 50 RIPE

스테이커 내부(하루 450 RIPE):
- RIPE LP   45% = 하루 202.5 RIPE
- GREEN LP  25% = 하루 112.5 RIPE
- sGREEN    15% = 하루  67.5 RIPE
- RIPE      15% = 하루  67.5 RIPE
```

**🎯 3단계: 풀에서 사용자 몫은 얼마인가요?**

```
사용자 포인트 = 잔액 × 블록
사용자 몫     = 사용자 포인트 ÷ 풀 포인트

예시: 1,000 RIPE를 100블록 동안 스테이킹
- 사용자 포인트: 1,000 × 100 = 100,000
- 풀 포인트: 1,000,000
- 사용자 몫: 10%
```

**🎯 4단계: 사용자 보상**

```
10% × 하루 67.5 RIPE = 하루 6.75 RIPE
RIPE당 $10이면 하루 $67.50
```

### 빠른 참고 표

| 사용자 작업 | 보상을 받는 곳 | 최대화하는 방법 |
| --- | --- | --- |
| RIPE LP 공급 | 스테이커(90%) · 45% 몫 | 더 큰 포지션을 더 오래 유지 |
| GREEN LP 공급 | 스테이커(90%) · 25% 몫 | 더 큰 포지션을 더 오래 유지 |
| RIPE 스테이킹 | 스테이커(90%) · 15% 몫 | 3년 잠금(포인트 3배) |
| sGREEN 예치 | 스테이커(90%) · 15% 몫 | 안정화 풀 수익과 결합 |
| GREEN 대출 | 차용자(10%) | 더 크고 오래 유지한 대출 |
| 기타 예치 | 예치자(0%) | 거버넌스가 켤 때까지 꺼짐 |
| 투표 선정 자산 | 투표자(0%) | 거버넌스가 켤 때까지 꺼짐 |

### 간단한 보상 추정기

가정: 하루 500 RIPE, RIPE당 $10, 위 가중치. "포인트 지분"은 사용자 포인트 ÷ 풀 포인트입니다. 모든 사람이 같은 기간 포지션을 유지했다면 포인트 지분은 잔액 지분과 같습니다.

**RIPE LP(스테이커의 45%):**

```
일일 RIPE ≈ RIPE LP 풀의 사용자 포인트 지분 × 202.5

예시: RIPE LP $100,000, 포인트 지분 1%
= 1% × 202.5 = 하루 2.025 RIPE = 하루 $20.25
= 연이율 약 7.4%
```

**GREEN LP(스테이커의 25%):**

```
일일 RIPE ≈ GREEN LP 풀의 사용자 포인트 지분 × 112.5

예시: GREEN LP $100,000, 포인트 지분 1%
= 1% × 112.5 = 하루 1.125 RIPE = 하루 $11.25
= 연이율 약 4.1%
```

**RIPE 스테이킹(스테이커의 15%):**

```
일일 RIPE ≈ RIPE 풀의 사용자 포인트 지분 × 67.5

잠금 배수는 이미 포인트 지분에 반영됩니다.
3년 잠금의 10,000 RIPE는 잠기지 않은 30,000 RIPE처럼 계산됩니다.

예시: 10,000 RIPE($100,000), 3년 잠금, 포인트 지분 3%
= 3% × 67.5 = 하루 2.025 RIPE = 하루 $20.25
= 연이율 약 7.4%, 매일 복리 적용 시 연수익률 약 7.7%
```

**sGREEN(스테이커의 15%):**

```
일일 RIPE ≈ sGREEN 풀의 사용자 포인트 지분 × 67.5

예시: sGREEN $100,000, 포인트 지분 2%
= 2% × 67.5 = 하루 1.35 RIPE = 하루 $13.50
= 연이율 약 4.9%
```

**GREEN 대출(발행량의 10%):**

```
일일 RIPE ≈ 사용자 대출 포인트 ÷ 전체 대출 포인트 × 50

예시: $500,000 대출, 포인트 지분 5%
= 5% × 50 = 하루 2.5 RIPE = 하루 $25.00
= 이자 비용에서 연이율 약 1.8% 환급 효과
```

## 보상 청구

### 청구하면 일어나는 일

1. 프로토콜이 사용자가 보유한 모든 볼트 및 자산의 포인트와 대출 포인트를 합산합니다.
2. 각 카테고리에서 사용자 몫을 계산하고 해당 수량의 RIPE를 발행합니다.
3. **Stake All**을 켜면 청구량 전부가 [거버넌스 볼트](../governance-and-economics/02-governance.md)로 들어갑니다. 컨트랙트를 직접 호출할 때도 이것이 기본값입니다.
4. Stake All을 끄면 유동 수령분을 받고 나머지에는 자동 스테이킹 비율이 적용됩니다. 예시에서는 75%가 스테이킹되고 25%가 지갑으로 전송됩니다.

자동 스테이킹된 RIPE에는 보상 잠금이 적용됩니다. 볼트 잠금 범위의 일정 비율이며 예시에서는 3년 × 33% ≈ 1년입니다. 기존 거버넌스 포지션과 섞이므로 잠금 해제일이 바뀔 수 있습니다. [포지션 관리](../governance-and-economics/02-governance.md#포지션-관리)를 참조하세요.

**청구 예시:** 1,000 RIPE를 받을 수 있습니다. Stake All 켜짐: 1,000 RIPE 전부 거버넌스 볼트에 잠깁니다. Stake All 꺼짐: 750 RIPE 잠금, 250 RIPE는 지갑으로 전송됩니다.

**권한 위임:** `canClaimLoot`를 부여하면 다른 사람이 대신 청구할 수 있어 자동 복리에 유용합니다.

**연기된 청구:** 보상을 쌓은 카테고리에 아직 지급할 수량이 없으면 이번 청구는 0으로 정산되고 포인트는 유지됩니다. 잃는 것은 없으며 나중에 다시 청구할 수 있습니다.

### 자동 스테이킹을 하는 이유

토큰이 바로 시장에 매도되게 하는 대신 자동 스테이킹은 보상과 함께 거버넌스 파워를 쌓는 장기 참여자 커뮤니티를 만듭니다. 토큰만 버는 것이 아니라 프로토콜의 미래에 대한 목소리도 얻습니다.

## 보상에 관해 자주 묻는 질문

### "왜 사용자 몫을 두 번 계산하나요?"

두 가지 입력값을 사용하는 하나의 계산으로 생각하세요. 어떤 파이에서 먹는지(카테고리에서 사용자 풀이 차지하는 몫), 그 파이에서 얼마나 큰 조각을 갖는지(풀에서 사용자 포인트 지분)를 봅니다. 디저트와 메인 요리가 다른 테이블에 있는 뷔페와 같습니다. 같은 테이블의 사람과만 경쟁합니다.

### "같은 카테고리의 다른 자산끼리 경쟁하나요?"

풀 수준에서만 경쟁합니다. RIPE 스테이커는 RIPE 몫을 놓고 다른 RIPE 스테이커와 경쟁합니다. RIPE LP 스테이커는 RIPE LP 몫을 놓고 같은 풀의 스테이커와 경쟁합니다. 풀 자체의 몫은 자산 가중치에서 나옵니다.

### "아무도 스테이킹하거나 대출받지 않으면 어떻게 되나요?"

참여한 사람에게 더 많이 돌아갑니다. RIPE 스테이커가 사용자 한 명뿐이라면 RIPE 몫 전부를 받습니다. 참여자가 없는 카테고리의 RIPE는 그대로 보관되며 다른 카테고리로 옮겨지지 않습니다.

## 일찍 참여한 사용자가 더 많은 RIPE를 받습니다

카테고리에서 사용자 몫은 사용자 포인트와 다른 모든 사람의 포인트를 비교해 정합니다. 지금은 다른 참여자가 적습니다. 예치와 대출이 늘어날수록 각 참여자의 몫은 줄어듭니다. 위 예시의 7.4%는 풀이 작을 때의 수치입니다.

프로토콜은 참여하는 사람에게 보상합니다. 참여하고 계신가요?
