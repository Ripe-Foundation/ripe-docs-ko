# 디레버리지: 너무 늦기 전에 위험 줄이기

청산은 괴롭습니다. 수수료, 강제 매도, 스트레스까지 따라옵니다.

대안은 디레버리지입니다. Ripe에 이미 보유한 sGREEN과 스테이블코인 포지션으로 부채를 줄입니다. 청산 수수료도, 키퍼 수수료도 없습니다. 자신의 자산으로 자신의 포지션을 보호하며, 주식 토큰은 건드리지 않습니다.

> **실시간 조건은 온체인에 있습니다.** 디레버리지에 사용할 수 있는 자산, 버퍼, 한도는 배포 네트워크마다 다르고 시간에 따라 바뀝니다. 이 페이지의 모든 수치는 예시입니다. [Params](https://params.ripe.finance)가 최종 기준입니다.

## 빠른 개요

두 가지 방법이 있습니다. **특정 자산 방식**은 사용할 자산과 상환 금액을 사용자가 선택합니다. **광범위 방식**은 담보 상환 구간에 들어간 뒤 다른 사람이 사용자의 포지션을 디레버리지합니다.

**주요 차이:**

| 항목 | 디레버리지 | 청산 |
| --- | --- | --- |
| 시점 | 특정 자산: 청산 중에도 언제든. 광범위: 담보 상환 구간부터 | 청산 기준치에 도달하거나 초과한 뒤 |
| 실행자 | 특정 자산: 본인, `canBorrow` 대리인, 신뢰받는 프로토콜. 광범위: 누구나 | 누구나(키퍼) |
| 사용 자산 | 사용자의 sGREEN과 스테이블코인 포지션 | 주식 토큰, WETH, 기타 변동성 담보 |
| 수수료 | 없음 | 청산 수수료 + 키퍼 수수료 |
| 사용자 통제 | 자산과 금액을 직접 선택 | 프로토콜이 선택 |

지갑에서 GREEN을 지불하는 것은 일반 상환이며 디레버리지가 아닙니다.

## 언제 디레버리지되나요?

### 특정 자산으로 직접 디레버리지

sGREEN 또는 스테이블코인 포지션 중 어떤 것을 어떤 순서로 사용할지, 부채를 얼마나 상환할지 직접 선택합니다. 기준치나 별도 허가 없이 청산 중에도 언제든 작동합니다. `canBorrow` 권한을 준 대리인이나 신뢰받는 프로토콜도 사용자를 위해 같은 작업을 할 수 있습니다.

### 제3자 디레버리지(담보 상환 구간)

담보 가치가 담보 상환 기준치 이하가 되면 누구나 광범위 경로로 사용자를 디레버리지할 수 있습니다.

* 포지션 건전성을 회복하는 데 필요한 부채 감소액이 상한이므로 그보다 많이 가져갈 수 없습니다.
* 여전히 수수료가 없습니다.
* 청산 진행 중에는 사용할 수 없습니다.

본인 계정에 광범위 경로를 호출해도 제3자와 같은 조건이 적용됩니다. 담보 상환 구간에 있어야 하고 같은 상한을 따릅니다. 대신 특정 자산 방식을 사용하세요.

## 디레버리지의 작동 방식

자산은 정해진 순서로 사용됩니다.

**1단계: 안정화 풀 포지션**

* **sGREEN**은 GREEN으로 전환된 뒤 소각됩니다.
* **LP 토큰**은 오라클 가치로 트레저리에 전송됩니다.
* 각 $1가 부채 $1를 상쇄합니다.

**2단계: 스테이블코인 담보**

* USDC와 기타 스테이블코인이 오라클 가치로 트레저리에 전송됩니다.
* 할인은 없습니다.

디레버리지 경로가 없는 자산은 건너뜁니다. 주식 토큰과 기타 변동성 담보는 사용하지 않으므로 디레버리지는 주식 포지션을 소비하지 않고 보호합니다. 다만 거버넌스에는 오라클 가치로 변동성 담보를 이동할 수 있는 두 가지 비상 도구(변동성 자산 디레버리지와 담보 스왑)가 있으며, 거버넌스만 실행할 수 있습니다.

정산 직전에 Ripe가 부채를 다시 읽습니다. 트랜잭션 도중 부채가 바뀌었다면 전체 작업이 되돌려집니다.

### 특정 자산 선택하기

```
예시: 주식 토큰 지키기

보유 자산:
- 주식 토큰($15,000)
- 10,000 USDC($10,000)
- 안정화 풀의 1,000 sGREEN($1,000)

부채: $12,000

디레버리지 순서:
1. sGREEN 먼저 → 부채 $11,000
2. USDC 다음   → 부채 $1,000
3. 주식 토큰   → 그대로 유지

결과: 부채 $1,000, 주식 토큰 유지
```

### 전액 상환 버퍼와 소액 잔여분

사용자 본인이나 신뢰받는 호출자가 부채 전액을 상환할 때, Ripe는 정확한 금액으로 마무리하기 위해 부채보다 아주 조금 많은 담보를 가져갈 수 있습니다. 초과분에는 고정 금액과 부채 비율 상한이 모두 적용되며 실제로는 반올림으로 생기는 소액 잔여분입니다. 아주 조금 부족하게 끝난 전액 상환을 탕감하는 경로도 컨트랙트에 있지만, 해당 상한의 초기값은 0이므로 거버넌스가 켜지 않는 한 아무것도 탕감되지 않습니다. 두 기능 모두 Underscore Earn 볼트 소유 포지션에는 적용되지 않습니다.

## [Underscore](https://underscore.finance/) 볼트를 사용하나요?

Underscore 볼트는 디레버리지를 포함한 자체 Ripe 포지션을 관리합니다. 사용자가 출금할 때 볼트가 어떻게 대출하고, 디레버리지하고, 조정하는지는 해당 볼트에 따라 다릅니다. [Underscore Protocol 통합](02-borrowing.md#underscore-earn-볼트-통합)을 참조하세요.

## 디레버리지 권한 위임

* **`canBorrow`** 권한은 대리인이 특정 자산으로 사용자를 디레버리지할 수 있게 합니다. 대출 권한과 같은 플래그입니다.
* 대리인이 자산, 순서, 금액을 선택합니다.
* 여러 계정을 처리하는 배치에서도 계정별 권한을 각각 확인합니다.

## 디레버리지해야 할 때

청산까지 기다리지 마세요. 다음과 같은 때 디레버리지하세요.

* 변동성이 커질 때
* LTV가 경고 구간에 가까워질 때
* 특정 자산의 노출을 줄이고 싶을 때
* 담보 구성을 바꿀 때

## 전체 흐름에서의 디레버리지

```
건전 → 경고 → 담보 상환 구간 → 청산 구간
  |      |          |                 |
언제든  언제든     + 담보 상환       청산 진행 중에도
디레버리지        + 광범위 디레버리지 직접 디레버리지 가능
```

* **담보 상환**: GREEN 보유자가 사용자의 부채를 $1로 지불하고 오라클 가격의 담보를 가져갑니다.
* **디레버리지**: 사용자의 sGREEN과 스테이블코인이 수수료 없이 부채를 상환하며, 사용할 자산을 선택할 수 있습니다.
* **청산**: 수수료가 붙는 강제 매도이며 최후의 수단입니다.

전체 흐름은 [청산](04-liquidations.md)을 참조하세요.

## 위험을 직접 통제하기

청산은 최악의 상황입니다. 디레버리지는 도구입니다.

1. 포지션을 확인하세요.
2. 안정화 풀에 sGREEN을 두거나 포지션에 스테이블코인을 보유하세요. 이것이 디레버리지 연료입니다.
3. 다른 사람이 대신 행동하게 하려면 권한 위임을 설정하세요.
4. 늦기 전에 일찍 디레버리지하세요.

청산 기준치보다 앞서 움직이세요. 통제권을 유지하세요.
